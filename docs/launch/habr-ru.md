# Черновик статьи для Хабра

Отдельная адаптация, не дословный перевод. Публикацию выполняет владелец. Весь код ниже взят из репозитория
https://github.com/gggggggggg999/ci-explain.

## Как я написал ci-explain: объяснение упавшего CI по логу, где каждый вывод подтверждён строками

Упавшая сборка редко бывает загадкой, но ответ спрятан среди тысяч строк. Мне нужен был инструмент, который
говорит, что упало, и показывает строки, которые это доказывают. Он должен работать офлайн, а ИИ подключать
только по моей просьбе.

### Сначала доказательства

Правило обязано вернуть строки лога, на которые опирается, иначе вывода нет:

```ts
const m = rule.match(ctx);
if (!m || m.evidence.length === 0) continue; // нет доказательств, нет вывода
```

Если ни одно правило не сработало, инструмент не выдумывает причину: он показывает самое «ошибочное»
место лога и честно пишет, что причина не распознана.

### Номера строк исходного файла

Нормализация убирает ANSI-цвета, CRLF, перезаписи `\r` у прогресс-баров, префиксы времени и схлопывает
повторы, но доказательство должно указывать на настоящую строку настоящего файла. Поэтому у каждой строки
хранится исходный номер:

```ts
export interface LogLine {
  n: number; // номер строки в ИСХОДНОМ входе
  text: string;
  repeat: number; // сколько одинаковых строк подряд схлопнуто в эту
}
```

Если лог больше лимита, анализируется его конец (причина обычно в конце), но номера всё равно считаются от
начала исходного файла. Это проверено тестом на 40-мегабайтном входе.

### Каскады в одну находку

Одна пропавшая переменная порождает десятки ошибок TypeScript. Правило сворачивает их в одну находку со счётчиком
и тремя первыми строками. Симптом вроде «Process completed with exit code 1» ранжируется ниже причины и
скрывается, если причина найдена.

### Секреты и почему фейковые токены собираются в тестах

Редакция идёт до анализа, поэтому ни находки, ни выгрузки, ни запрос к ИИ не содержат значений, только
количество замен. Чтобы в репозитории не лежало ничего, похожего на секрет (его заблокирует push protection
GitHub и сканеры), тестовые токены собираются на лету:

```ts
const fake = {
  ghp: 'gh' + 'p_' + 'x'.repeat(36),
  aws: 'AK' + 'IA' + 'ABCDEFGH12345678',
};
```

Отдельный тест прогоняет весь репозиторий через сам редактор и падает, если находит готовую строку-секрет.
Редакция по шаблонам не ловит всё, это прямо написано в документации, и поэтому есть `--show-prompt`: он
печатает точный текст запроса и ничего не отправляет.

### Лог это недоверенный ввод

Лог может составить автор pull request. Поэтому из лога ничего не исполняется и не попадает в shell, регулярки
простые и якорные, строки обрезаются до применения regex, а тест гоняет патологические строки по всем правилам с
лимитом времени. В ИИ-слое лог лежит между фиксированными маркерами отдельным сообщением, ответ обязан быть
JSON заданной формы (проверка Zod), а из текста вычищаются HTML, ссылки и упоминания. Промпт не устраняет
риск prompt injection, поэтому у модели нет инструментов и она ничего не может сделать.

### Безопасный Markdown

Вывод можно вставлять в job summary: проза экранируется, `@mentions` и `#123` нейтрализуются, а доказательства
лежат в блоке кода с ограждением длиннее любой серии обратных кавычек внутри текста, так что лог не сможет
«закрыть» блок. Размер ограничен значением ниже лимита job summary в 1 MiB на шаг, указанного в документации GitHub.

### Чему научил реальный вывод

Правила, написанные по памяти, ошибались в мелочах. Запуск настоящих инструментов показал, что сообщение npm про
отсутствующий lockfile отличается от того, что я помнил, а Yarn пишет «was run with», а не «was executed with».
Настоящий лог GitHub Actions показал, что `##[group]` встречается и внутри шагов, поэтому шаги начинаются со строк
`##[group]Run `. Правила, формат которых воспроизвести не удалось, помечены как непроверенные и ограничены уровнем
medium.

### Честные ограничения

34 правила, проверены на синтетических фикстурах и локально воспроизведённом выводе. Цифр точности нет: нет набора
реальных логов. Источник GitHub и ИИ-слой проверены только на моках. Пакет пока не в npm, собирается из исходников.
